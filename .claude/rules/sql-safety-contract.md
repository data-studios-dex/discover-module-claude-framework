# 🔒 SQL Safety and Query Contract Rules

All SQL generation, validation, and execution within the framework must strictly obey these safety and semantic contracts:

## 1. Absolute Read-Only Enforcement
- **Allowed Statements**: `SELECT` queries and dialect-specific read-only introspection statements only.
- **Prohibited Keywords**: Under NO circumstances may any generated SQL contain:
  `DROP`, `TRUNCATE`, `DELETE`, `INSERT`, `UPDATE`, `ALTER`, `CREATE`, `REPLACE`, `GRANT`, `REVOKE`, `EXEC`, `EXECUTE`, `LOCK`.
- **Single-Statement Rule**: Multiple semicolon-delimited queries (`SELECT ...; DROP ...`) are strictly prohibited and will be rejected at the AST validation gate (G2/G4).

## 2. Data Quality (DQ) Rule Contract: Scalar Violation Count
All DQ verification rules generated by `dq_rulegen` must adhere to the single scalar violation count contract:
```sql
SELECT COUNT(*) AS violation_count
FROM "<schema>"."<table>"
WHERE <failure_condition>;
```
- **Rule of Non-Compliance**: The query must count records that **VIOLATE** the business rule.
  - Zero violations (`violation_count == 0`) = Rule **PASSES**.
  - Greater than zero violations (`violation_count > 0`) = Rule **FAILS**.
- Do NOT return actual row payloads in rule checks unless explicitly writing an exploratory diagnostic query.
- Use explicit alias `AS violation_count`.

## 3. Database Dialect Quoting & Identifier Conventions
- **PostgreSQL**:
  - Always quote identifiers in double quotes when mixed-case or reserved: `SELECT COUNT(*) FROM "bronze"."orders";`.
  - Prefer lowercase for all standard table and column references.
  - Use ANSI-compliant standard casting: `CAST(col AS numeric)` or `col::numeric`.
  - Always prefix tables with the target schema name if specified in the manifest.
- **SQLite**:
  - Use standard double quotes or square brackets: `SELECT COUNT(*) FROM [customers];`.
  - No `FULL OUTER JOIN` support; use `LEFT JOIN` or `UNION ALL`.
  - For date operations, use `strftime('%Y-%m-%d', col)` or `datetime(col)`.

## 4. Performance & Resource Constraints
- Always avoid unbounded Cartesian products (`CROSS JOIN`).
- For profiling statistics, aggregate across columns in a single scan query where possible:
  ```sql
  SELECT
      COUNT(*) AS total_rows,
      COUNT("email") AS non_null_email,
      COUNT(DISTINCT "email") AS distinct_email
  FROM "<schema>"."<table>";
  ```
- Top frequency value queries must always include an explicit `LIMIT` clause (default: `LIMIT 10`).
